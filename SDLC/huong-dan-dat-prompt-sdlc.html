Hướng dẫn đặt prompt để sản xuất phần mềm đúng quy trình SDLC

Dựa trên bộ 45 agent & skill plugin developer — dev-quality-toolkit · Cập nhật 2026-10-08

0. Nguyên tắc chung khi đặt prompt

  1. Một prompt — một agent, một việc. Nếu công việc trải nhiều giai đoạn (vd. "làm rõ yêu cầu rồi thiết kế luôn"), tách thành nhiều lượt hỏi tuần tự, đừng gộp vào một câu.
  2. Nêu rõ trạng thái hiện tại — "chưa có code", "kiến trúc đã chốt chưa", "migration đã viết ra chưa". Đây là trục Claude Code dùng để chọn đúng agent giữa các cặp dễ nhầm (vd. threat-modeler trước code vs security-auditor sau code đã viết).
  3. Nêu rõ file/module cụ thể thay vì mô tả chung chung — "review giúp file order.py" tốt hơn "review code giúp".
  4. Phần lớn agent ở giai đoạn Thiết kế/Kiểm thử/Vận hành chỉ phân tích & báo cáo, không tự sửa file — nếu cần hành động, nối thêm yêu cầu dùng agent có quyền Write/Edit tương ứng.
  5. Không chắc nên dùng agent nào? Gọi /developer:agent-advisor kèm mô tả việc — nó đọc trực tiếp plugin.json để tư vấn đúng theo hiện trạng repo.

1. Tổng quan pipeline 6 giai đoạn

1. Thu thập & Phân tích yêu cầu │ ▼ 2. Thiết kế (kiến trúc, API, dữ liệu, UI, bảo mật) │ ▼ 3. Phát triển (coding) ──────┐ │ │ (lặp lại mỗi sprint/iteration) ▼ │ 4. Kiểm thử (testing) ───────┘ │ ▼ 5. Triển khai (deployment) │ ▼ 6. Vận hành & Bảo trì (operations & maintenance)

Phần mềm hiện đại hiếm khi đi qua 6 giai đoạn này một lần rồi kết thúc — đây là một vòng lặp: mỗi tính năng mới, mỗi bản sửa lỗi đều đi qua lại từ bước 2 đến bước 6.

2. Giai đoạn 1 — Thu thập & Phân tích yêu cầu

Tình huốngAgent
Yêu cầu nghiệp vụ còn mơ hồ, cần user story + acceptance criteriarequirements-analyst
Yêu cầu đã rõ, cần văn bản hóa thành SRS chính thứcsrs-writer
"Sếp tôi muốn có tính năng 'thông báo cho khách hàng khi đơn hàng có vấn đề' nhưng nói còn rất mơ hồ, giúp tôi làm rõ thành user story."
"requirements-analyst đã làm rõ xong yêu cầu export đơn hàng ra CSV, giúp tôi viết thành tài liệu SRS chính thức."
